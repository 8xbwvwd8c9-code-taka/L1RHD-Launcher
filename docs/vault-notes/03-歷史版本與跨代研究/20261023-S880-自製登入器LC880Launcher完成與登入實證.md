## 關鍵技術發現：C_LOGIN 是整包密文

在遊戲登入畫面輸入帳密後，S880 回報 `不合法的帳號長度:127.0.0.1/x?r&穾c蟭…`。取證後確認：

```text
C_LOGIN 明文前 48B  = 1F9E56ED725EBB270D4856B19C759CB2…
首個 NUL 位置       = 130 / 總長 292B
ASCII               = [.x.r&.@c......xqld#..|Q.C7...]
NUL 後 60B          = 00009FA9724F36A55BEEF5027A2C9242BC…
```

| 位置 | 內容 |
|---|---|
| `[0]` | `0x1F`（opcode C_LOGIN） |
| `[1..129]` | 129 B 高熵密文 |
| `[130]` | 唯一 NUL |
| `[131..291]` | 161 B 密文 |

`C_AuthLogin.readS()` 把前 129 B 當帳號 → 長度爆表 → 斷線，密碼驗證根本沒跑到。
**因此「在遊戲內輸入帳密」架構上不可能成功**，帳密必須由登入器代收。

解法：relay 解密後把前綴換成 `acct\0pwd\0`，**保持 292 B 等長**再加密送出。
C→S 是流加密，長度一變後面全部錯位。

## S880 連線限制與修補

`LanSecurityManager.checkAccept()` 有三重檢查：

| 機制 | 預設 | 影響 |
|---|---|---|
| `BANIPMAP` | 異常封包時寫入 100 秒 | 一次手滑斷線 → 整個 IP 封鎖 100 秒 |
| `ONEIPMAP` | `ISONEIP=false` | 未啟用 |
| `ONETIMEMILLISMAP` | `ONETIMEMILLIS=20000` | 同 IP 20 秒只能連一次 |

`ipcheck.properties` 的 `#ONETIMEMILLIS = 3000` 是註解掉的，實際走預設 20000。

本機修補（單機測試環境）：

```text
ClientExecutor.java  移除 LanSecurityManager.BANIPMAP.put(_ip.toString(), 100)
ipcheck.properties   ONETIMEMILLIS = 0
```

`ONETIMEMILLIS = 0` 時 `checkAccept()` 不寫入 map，20 秒限制自然失效，不需改 Java。
對外開放前應改回 `3000` 並恢復封鎖。

## 修補後驗證（原始 TCP，不經登入器）

```text
1 正常連線          OK 收到 15B 0f00
2 連上後立刻斷線
3 立刻重連          OK        ← 舊版被 20 秒限制拒絕
4 送出 2000B 異常封包
5 異常後立刻重連    OK        ← 舊版被 100 秒封鎖拒絕
6 再連一次          OK
```

## 踩過的坑（教訓）

1. **重試不可換來源 IP**。改用 `127.0.0.2` 會讓加解密狀態與新 Init key 錯位，改寫後的封包變亂碼（11:19、11:20 實證）。
2. **改寫必須等長**，否則流加密位移全毀。
3. **Init 由伺服器主動送出**（`EncryptExecutor.outStart()` 必寫 15 B），所以「取 Init 失敗」只可能是連線被拒。
4. **砍掉 Lin.bin 不等於連線關閉**。S880 收不到 FIN，舊 session 會擋新連線。
5. **失敗要回顯**。UI 最小化後毫無反應會讓使用者以為壞了；已加 watcher，14 秒後若 `Lin.bin` 消失就把視窗叫回來並附原因。
