## 2. 確認後的標準流程（JJ-000025 原文流程）

```text
維護者端：
  產生 Update.ini（version 版本號 + 要更新的檔案清單）＋ 補丁壓縮檔
    → 上傳到更新空間（FTP 專用目錄；教學強調上傳/下載帳號分離）
玩家端：
  登入器啟動 → 讀 Login.cfg 取得「自動更新空間位置」
    → 抓 Update.ini 比對 version vs 本地 Login.ini.Updated
    → 較新 → 下載清單內檔案並解壓至主程式目錄
    → 執行 eat.exe 進行吃檔（把鬆散資源封裝進 PAK）
```

**eat.exe 身份校正**：天R/歐霸天堂目錄的 `Eat.exe` 在 JJ 教學語境就是**吃檔器**（解壓後把資源封進 PAK）；但 vault 手冊 §8.2 已實證天R 版 `eat.exe 1 1 global` 會安裝**全域鍵盤/訊息鉤子**（Defender 判定風險、行為不透明）→ 自動化不應依賴它。

## 3. 可行性矩陣（對照 RHDLauncher B4+ 現況）

| 步驟 | 狀態 | 證據/缺口 |
| :--- | :--- | :--- |
| 抓取 manifest＋版本/內容比對 | ✅ 已具備 | `updater.rs` 逐檔 MD5（比 JJ 的 version 整數更精細；歐霸天堂同路線） |
| 下載差異檔 | ✅ 已具備 | http-only（私服內網）；**若更新空間要放 GitHub 需加 ureq TLS feature（一行改動）** |
| 鬆散資源套用（data\*.tbl/xml） | ✅ 已具備 | 暫存改名＋MD5 複驗；歐霸天堂官方契約也是鬆散檔（Login.local 167 條全為 `data\`） |
| **PAK 層吃檔**（圖檔/sprite/dialogue 封進 PAK） | ⚠️ 未做 | 三路線：(a) eat.exe——不建議（鉤子+不透明）；(b) `LineageAIResourceToolkit` `pak add/replace`（能力已存在，屬「寫回來源」危險命令，需授權＋備份紀律）；(c) 先盤點哪些資源真需要進 PAK——鬆散可覆蓋者用現有引擎即可 |
| **更新空間（「倉庫」）** | ❗決策點 | 見 §4 |

## 4. 「更新檔上傳到倉庫」的空間選擇（關鍵評估）

| 選項 | 可行性 | 問題 |
| :--- | :--- | :--- |
| **GitHub 公開倉庫**（L1RHD-Launcher） | ❌ 不建議 | **紅線衝突**：倉庫規則明文「客戶端 BIN／資源不入庫」（NCSOFT 衍生物＋公開倉庫版權風險）；單檔 100 MB 上限（PAK 動輒 30–180 MB，需 LFS，免費頻寬 1 GB/月）；raw 為 https（需 TLS 改造） |
| **GitHub 私有倉庫** | ⚠️ 技術可行 | 玩家端需內嵌 token 才能抓＝金鑰洩漏風險；同上大小/頻寬限制 |
| **私服主機自架靜態 HTTP**（或 FileZilla FTP，JJ-000023） | ✅ **建議** | 與 JJ 教學、歐霸天堂官方（自家 HTTP）、我方引擎（http-only）三者一致；零新依賴；上下傳帳號分離原則照 JJ；缺點＝主機需在線 |
| Git 倉庫 pull 式（登入器 git clone） | ⚠️ 過重 | git 依賴入登入器、公開紅線同上 |

> 補充：`X:\L1RHD\L1RHDserver` 或任意內網主機起一個靜態檔案服務（含 `python -m http.server`）即滿足我方引擎；要對外公網則加反代/防火牆規則，屬運維配置。

## 5. 若施工的建議順序（本次未執行）

> [!NOTE]
> **2026-10-31 使用者已就 §4/§5 拍板**（靜態 HTTP／資源落客戶端絕對路徑／自動吃檔／吃檔結束前閘門），正式規格成文於 **[[20261031-L1RHD自動更新企畫書]]**（APPROVED-PENDING-IMPL），施工以該篇為準。

1. **零開發**：先以現有引擎驗證鬆散檔吃檔閉環——私服起靜態 HTTP → 生成 manifest（工具包 tbl/pak 抽出＋MD5）→ `launcher.json` 填 URL → 實機驗收。
2. **小開發**：zip 補丁包支援（JJ 式壓縮包下載＋解壓；`zip` crate，成本低）。
3. **中開發（需授權）**：PAK 層吃檔——自動化 `pak add/replace`＋來源備份＋交易紀律（對照 inproc.cpp 模式），或借鑑 L1J-Wanted 的 PAK 比對解包設計。
4. **伴隨工程**：manifest 生成腳本正式化（`DataAll` 權威來源＋MD5 清單產出，接 B4 筆記 §8-3 殘留待辦）。
